# Tactile

**Cible tactile de 44 px minimum** (`--tap`, utilitaire `.tap-target`). Ce n'est pas une
marge de confort, c'est la spec.

## Les deux leviers

Ils ne disent pas la même chose, et c'est toute la question : un grand écran tactile existe.

| | | |
| --- | --- | --- |
| `md:` | `min-width: 48rem` | La mise en page générale |
| `sm:` | `min-width: 40rem` | Un dialogue qui passe de feuille à boîte |
| `pointer-coarse:` | `(pointer: coarse)` | La taille des cibles. Le doigt, pas la largeur |

D'où la taille `sm` de `Button` :

```
h-11 px-3 text-sm gap-1.5 md:h-9 pointer-coarse:h-11
```

Petit au large *et* à la souris, jamais petit au doigt.

`lg:` et `xl:` ne servent pas — l'interface a deux états, pas quatre.

## Encoches

Nommées plutôt qu'appelées directement par `env()` : une barre de hauteur fixe doit pouvoir
*ajouter* l'encoche à sa hauteur, ce que `calc()` ne sait pas faire depuis une classe
utilitaire. Les nommer permet aussi de rejouer la géométrie d'un iPhone sur un poste de
développement.

| | |
| --- | --- |
| `.pt-safe` / `.pb-safe` | Rembourrage d'encoche, haut et bas |
| `.header-bar` | Barre fixe qui descend sous l'encoche |
| `.app-layer` | Le calque de l'application, dimensionné sur le viewport visuel |

Trois pièges, tous rencontrés pour de vrai :

**`h-[var(--header-height)]` et `pt-safe` sur le même élément ne se combinent pas.** La boîte
garde 52 px, le contenu est poussé de 59 px, et il déborde donc *sous* la barre, où la vue le
recouvre. Invisible au navigateur, où l'encoche vaut zéro ; cassé dans la PWA installée.
C'est `.header-bar` qui règle ça.

**iOS zoome sur un champ dont le texte fait moins de 16 px**, et ce zoom ne se défait jamais
tout seul : il laisse la page décalée et un défilement horizontal parasite. D'où la règle
`font-size: 1rem` sur `input`/`select`/`textarea` en `pointer: coarse`, posée **hors de toute
couche** pour l'emporter sur les utilitaires Tailwind.

**Le document ne défile jamais.** L'application est un calque fixe dimensionné sur le viewport
visuel. Sans ça, iOS fait rebondir la page derrière le clavier et décale tout ce qui est
positionné en fixe.

Ces trois règles ne se vérifient que sur un téléphone, dans la PWA installée — pas dans ce
catalogue.
